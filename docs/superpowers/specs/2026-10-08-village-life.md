# Village life V1

Implement the approved next step: persistent account location, daily shared life AP (100), gathering (one AP produces ten herbs or ten of one random crop), and a shared daily pool of 30,000 per specialty. Central city has independent herb and farm pools. All resets use Asia/Seoul midnight, discard unused AP/stock, and are materialized lazily; API responses always represent the current day.

Use independent private tables rather than changing the legacy expedition save schema. RPCs require the current gameplay lease, revoke anonymous execution, serialize player operations and lock the target town for shared stock. Gather requests use UUID receipts: replay never consumes or awards twice, conflicting reused requests fail. Random crops are generated exclusively on the server, per gathering action. Validate position, resource, count 1..100, AP and stock before mutation. Reject whole batches that exceed availability. Stored materials are a dedicated life inventory for future crafting, not legacy ore/leather.

All towns start neutral, zero tax, no upgrades or owner bonus until the later conquest integration. Replace example ownership with authoritative data. Village life requires Google sign-in; guests see a sign-in prompt and cannot earn resources or save travel. UI supports direct travel, current-town life entry, quantities, stock, inventory and recovery of ambiguous requests. Key controller by account and lease, discard late responses after teardown. Do not change hunting, combat, wallet or expedition authority. Verify executable SQL tests including replay, wrong location, capacity, midnight reset and privileges; UI regression, typecheck and build; deploy additive SQL before frontend commit.
