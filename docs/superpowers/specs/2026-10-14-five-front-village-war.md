# 5전선 마을 공성전 설계

상태: 규칙 합의 완료, 구현 전 설계 검토본. 이 문서는 기능 구현·서버 배포 완료를 뜻하지 않는다.
기준 커밋: ec4144ba2d1f1f97fcd21f08a83b50237775404a.

## 목적과 범위

11개 영지에서 여러 길드가 5개 전선을 경쟁한다. 전선마다 실제 캐릭터 한 명이 수비하고, 수비자를 처치한 공격자가 바로 새 수비자가 된다. 길드가 점령한 전선의 유지 시간을 점수로 환산한다. 모바일 기존 전투 화면을 사용한다.

1차 범위는 서버 상태, 시작 전 수비 배치, 길드장의 배치 해제, 시작 시 스냅샷 고정, 빈 전선 즉시 점령, 동시 요청·중복 차감 방지 및 해당 화면 연결이다. 자동 PvP·점수 정산·보상은 다음 구현 단위이며, 그 기능이 연결되기 전에는 완성된 공성전으로 공개하지 않는다. 구형 3전선 점령전의 시간·입찰·전투 함수를 변경하지 않고 별도 시스템으로 구현한다.

## 합의된 규칙

- 전쟁은 60분. 각 전선은 분당 1점이며 실제 유지 시간을 연속 누적한다. 최다 점령 보너스는 없다.
- 누적 150점 선착순으로 조기 승리. 종료까지 미달이면 최고 점수 길드가 승리한다.
- 동점이면 종료 시 보유 전선 수를 비교한다. 그래도 동점이면 영지 소유권을 변경하지 않는다. 소유자가 없으면 중립을 유지한다.
- 전선은 1~5번, 전선당 수비자 1명. 같은 캐릭터는 모든 진행 중인 영지를 합쳐 한 전선에만 배치·수비 가능하다. 수비 중에는 다른 전선을 공격할 수 없다.
- 전쟁 시작 전 5분 동안 기존 소유 길드원이 빈 전선에 자기 캐릭터를 배치한다. 길드장은 길드원의 배치를 해제할 수 있다. 전쟁 시작 이후 임의 해제·교체는 금지한다.
- 시작 시 빈 전선은 중립이며 점수를 생성하지 않는다. NPC를 배치하지 않는다.
- 전쟁 중 참가 길드원이 도전권 1장을 내고 빈 전선을 전투 없이 점령한다. 점령한 사람이 새 수비자이고 점령 순간부터 점수를 얻는다. 개인 공격 쿨타임 30초를 적용한다.
- 공격자는 매 공격 HP·MP 전부 회복한다. 사냥의 HP·MP·포션·활력·PvE 음식과 분리한다.
- 수비자의 전투 후 HP·MP를 유지한다. 새로운 점령자의 HP·MP는 전부 회복한다.
- 전투는 100턴까지. 그 안에 수비자를 처치하지 못하면 수비 성공이며 감소한 HP·MP는 유지한다.
- 수비 성공 시 50% 확률로 수비자에게 도전권 1장을 지급한다. 수비자 없는 점령에는 지급하지 않는다. 보상 난수와 결과는 서버에서 한 번만 결정해 영수증에 보관한다.
- 공격은 전선당 한 번에 하나만 계산한다. 대기열과 자동 재공격은 없다. 결과를 읽는 시간은 잠금에 포함하지 않는다.
- 수비자가 변경된 공격은 차감·쿨타임 없이 거절한다. 같은 수비자에게 다른 공격자가 먼저 피해를 줬다면 최신 HP·MP로 공격한다.

## 기존 기능과 연결

`private.village_war_declarations`와 선전포고 영수증을 재사용한다. 길드장 도전권 100장 등록 비용은 유지한다. 해당 주·영지에 선전포고한 길드는 공격 가능하고 기존 소유 길드는 방어와 탈환에 참여할 수 있다.

기존 일정인 토요일 22:00 KST 시작을 유지하는 설계 가정이다. 새 전쟁의 배치 구간은 21:55~22:00, 전투 구간은 22:00~23:00이다. 구형 점령전의 22:00~22:30 일정은 별도로 유지한다. 시작 시간 변경 요청이 있으면 새 전쟁의 일정만 바꾼다.

지도 `WORLD_TOWNS`의 예시 길드·세율은 소유권 근거로 사용하지 않는다. 새 서버 소유권 레코드가 없는 마을은 중립으로 초기화하고 UI에 중립으로 표시한다. 기존 플레이어·길드에 임의 소유권을 지급하지 않는다.

## 서버 데이터 구조

모든 변경 가능한 공성전 테이블은 private 스키마에 두고 RLS 및 직접 접근 금지를 적용한다.

- `village_war_owners`: 영지별 실제 소유 길드와 소유권 확정 시각.
- `village_war_events`: 주차·영지별 이벤트, 시작·종료·배치 시각, 이전 소유 길드, 상태 및 최종 승자. 주차와 영지 조합은 유일하다.
- `village_war_fronts`: 이벤트별 5행. 소유 길드, 수비자, 장비·스킬·능력치 스냅샷, HP·MP, 수비자 교체 번호, 상태 변경 번호와 점령 시각.
- `village_war_actor_state`: 사용자별 현재 수비 전선과 공격 가능 시각. 모든 영지의 동시 행동을 이 레코드로 제어한다.
- `village_war_receipts`: 사용자·요청 UUID의 유일 영수증. 동작 종류·영지·전선·요청 내용·결과를 저장하고 다른 내용의 UUID 재사용은 거절한다.
- 점수·전투 상세·개인 기여도 테이블은 2차 구현에서 추가한다. 사용자에게 다른 사람의 원본 저장 데이터나 비공개 설정을 반환하지 않는다.

수비자 교체 번호는 수비자 배치·제거·점령 교체마다 증가한다. 상태 변경 번호는 같은 수비자의 피해·MP 변경에도 증가한다. 두 번호를 구분해 피해만 누적됐을 때까지 불필요하게 공격을 취소하지 않는다.

## RPC와 권한

- `get_village_war_state`: 서버 시각·단계·참가 길드·5전선·본인 권한·도전권·쿨타임 조회.
- `place_village_war_defender`: 자기 캐릭터 배치. 기존 소유 길드의 실제 멤버인지, 배치 구간인지, 빈 전선인지, 다른 전선 수비 중인지 검증.
- `remove_village_war_defender`: 현재 소유 길드장만 시작 전 배치 해제 가능. 대상의 배치 번호가 달라졌으면 해제하지 않는다.
- `claim_empty_village_war_front`: 참가 권한, 시간, 예상 교체 번호, 빈 전선, 도전권 및 개인 행동 상태를 검증하고 즉시 점령.
- 실제 수비자가 있는 전선의 공격 RPC는 2차 PvP 엔진과 함께 추가한다. 1차에서 전투처럼 보이는 임의 HP 감소나 성공 결과를 만들지 않는다.

모든 RPC는 로그인·활성 플레이 세션을 검증한다. 권한과 캐릭터 스냅샷은 서버 저장 상태에서 읽으며 클라이언트가 보내는 길드·스탯·HP를 신뢰하지 않는다. 배치 시에는 캐릭터 식별자를 저장하고 시작 경계에서 서버 세팅을 스냅샷으로 고정한다. 이후 새 점령자의 수비 스냅샷은 해당 점령 시점에 고정한다.

## 트랜잭션과 동시성

각 변경 요청은 활성 세션 확인 후 사용자·요청 UUID의 트랜잭션 잠금으로 중복 실행을 막는다. 이미 완료된 영수증이 있으면 저장된 결과를 반환한다. 진행 중인 같은 요청을 새 공격으로 실행하지 않는다.

잠금 순서는 이벤트 → 사용자 행동 레코드(복수 대상이면 사용자 ID 정렬) → 전선 → 도전권 지갑으로 일관되게 유지한다. 다른 전선의 동시 행동에 필요한 이벤트 공통 접근은 서로 충돌하지 않는 방식으로 처리한다. 이벤트 최종 종료는 독점 접근과 재검증이 필요하다.

특정 전선과 사용자 행동의 충돌은 NOWAIT 또는 트랜잭션 단위 try-lock으로 즉시 거절한다. 잠금을 기다리는 공격 대기열을 만들지 않는다. 전선·참가·교체 번호를 재검증한 다음에만 도전권을 차감한다.

차감, 스냅샷, 수비 배치, 교체 번호 증가, 개인 쿨타임 및 성공 영수증은 하나의 트랜잭션으로 저장한다. 중간 실패 시 모두 롤백한다. 재시도는 같은 UUID를 사용하며 같은 성공에 다시 비용을 부과하지 않는다.

무효 요청·잠금 충돌·수비자 변경·잔액 부족은 전선 상태, 지갑, 쿨타임을 변경하지 않는다. 빈 전선에 대한 동시 요청에서는 유효한 요청 하나만 성공한다. 처리 순서는 클라이언트 클릭 시각이 아니라 서버가 잠금과 검증을 통과한 순서다.

## 시간 경계와 점수의 후속 설계

수비 배치는 서버 시각 기준 `[시작-5분, 시작)`에만 허용한다. 전투는 `[시작, 종료)`에만 시작한다. 경계에서 시작·종료 상태 전환을 서버가 수행하고 요청이 경계를 넘으면 차감 전에 재검증한다.

2차 점수는 정각 스냅샷이 아니라 각 전선 소유 구간의 실제 시간 적분으로 계산한다. 60초의 전선 점령을 1점으로 환산하고 내부에는 정밀 시간을 보관한다. 교체 시 과거 길드의 획득 시간을 먼저 반영한다. 목표 도달 시각을 계산해 그 이후 공격을 막고, 종료 시각 이후로 점수를 쌓지 않는다. 주기 정산과 조회 시 정산을 결합해 마지막에 접속한 길드가 승자를 결정하지 않도록 한다.

## 화면과 요청 복구

현재 5전선 화면을 실제 서버 상태로 연결한다. 배치 단계에는 빈 자리와 자기 배치 버튼, 길드장에게는 해제 버튼을 표시한다. 전투 단계에는 빈 전선 점령 버튼을 표시하고 수비 중인 전선의 공격은 2차 연결 전까지 명확하게 비활성화한다.

요청을 보내자마자 버튼을 잠그고 미확인 UUID를 계정별로 보관한다. 응답 유실 시 기존 요청을 재확인하며 새 UUID로 자동 재공격하지 않는다. 로그아웃·계정 변경 시 이전 계정의 결과를 새 계정에 반영하지 않는다. 새 수비자 변경 오류에는 갱신된 전선과 차감 없음 안내를 표시한다.

## 1차 검증과 공개 조건

- 시작 5분 전·시작 직전·시작 정각·종료 정각의 배치와 점령 허용 여부.
- 멤버의 자기 배치, 길드장의 해제, 다른 길드·일반 멤버의 해제 거절.
- 같은 캐릭터의 여러 영지·전선 중복 배치 거절.
- 시작 시 스냅샷 고정, 접속 종료와 장비 변경으로 수비 상태가 변하지 않음.
- 실제 병렬 연결로 동일 빈 전선 점령 요청을 동시에 실행: 한 명만 소유하고 성공한 요청만 1장 차감.
- 동일 UUID 재시도·내용이 다른 UUID 재사용·응답 유실 복구.
- 한 사용자의 서로 다른 전선 동시 요청과 쿨타임 우회 차단.
- 예외 발생 시 지갑·배치·쿨타임·영수증 전체 롤백.
- 새 소유자 없는 영지는 중립이고 예시 지도 데이터로 점수를 생성하지 않음.
- 모바일 320×568, 375×640, 430×740에서 배치·점령·상태 확인 버튼이 잘리지 않음.

공개 공성전 활성화는 자동 PvP·점수·종료 판정과 실제 동시성 검증이 완료된 이후에 한다. 1차만 완성된 상태에서는 완전한 공성전이라고 보고하지 않는다.
