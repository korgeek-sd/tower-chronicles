# Game Mail Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement inline.

**Goal:** Server-owned mail with transaction summaries, claimable returns and independent 30-day order/mail expiry.
**Architecture:** Private mail rows and lease-validated RPCs; settlement and mail creation in the same transaction. Cron expires orders and purges expired mail; the UI reads and claims through authenticated RPCs.
**Tech Stack:** PostgreSQL/Supabase Cron, React, TypeScript.
**Spec:** User-approved conversation: six titles; partial proceeds immediate; residual sale assets in mail; 30 days from registration for orders, from delivery for mail.

## Global Constraints
- Preserve existing fees; purchases deliver immediately, sales settle immediately.
- No client-written rewards. Attachments claimed once, only at the hub.
- Purchase reserve refunds remain immediate. Sell returns require mail claim.
- Expired mail and unclaimed attachments disappear. No double expiry/cancel mail.
- Existing pre-update storage is preserved and remains claimable.

## Review Focus
- Account switch and delayed responses must not apply another account's assets.
- Partial fill followed by expiry returns only residual quantity.
- Expired orders must never match, even before cron runs.
- Manual deletion of unclaimed mail must be blocked.
- Duplicate claim and concurrent expiry must not duplicate rewards.
