# 장비 상자 거래소 보관함 검토

검토 대상은 구매자 보관함 지급 변경 1db458e와 취소·만료 반환 변경 150afda입니다.

| 경로 | 근거와 결과 |
| --- | --- |
| 체결 | 첫 변경의 마이그레이션 7~10행에서 장비 상자의 체결 수량을 구매자 보관함에 기록합니다. 장비 상자 분기에서는 즉시 지급 함수를 호출하지 않습니다. |
| 취소·만료 | 두 번째 마이그레이션의 close_market_order는 주문을 잠그고 미종결 상태를 확인한 뒤 미판매분만 판매자 보관함에 기록합니다. 두 종료 경로가 이 함수를 공유합니다. |
| 우편·알림 | 장비 상자 반환 우편의 첨부 수량은 0입니다. 운영 서버의 game_mail_notify 트리거는 알림을 만듭니다. 검토한 거래·주문·보관함 테이블에는 추가 지급 트리거가 없습니다. |
| 개별·일괄 수령 | ServerMarketScreen의 개별 수령은 storageId를 사용합니다. 두 서버 수령 함수 모두 활성 세션의 계정으로 행을 제한하고 잠근 뒤 지급 및 삭제합니다. |
| 권한 | 운영 서버에서 anon과 authenticated 모두 내부 주문 종료 함수의 실행 권한과 보관함 테이블의 직접 INSERT·UPDATE·DELETE 권한이 없습니다. |

이전 롤백 시험에서는 미체결 7개와 부분 체결 잔량 5개의 취소·만료 및 종료 요청 반복을 확인했습니다. 이번 검토에서는 두 커밋과 실제 화면의 수령 호출, 운영 권한과 트리거를 대조했습니다. 두 계정으로 실제 구매부터 양쪽 보관함 수령, 재접속까지 이어지는 통합 시험은 미검증입니다.

반환 항목은 보관함의 trade_id에 주문 ID를 저장합니다. 개별 수령은 storage_id를 사용하므로 현재 수령 경로에는 영향이 없지만, 이후 거래 기록을 연결하는 코드에서는 반환 항목과 체결 항목을 구분해야 합니다.
