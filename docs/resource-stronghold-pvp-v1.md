# 자원거점 실제 유저 쟁탈 V1

## 상태 머신

공용 거점은 `AVAILABLE → ACTIVE → CONTESTED → ACTIVE/COMPLETED/ABANDONED` 순서로 전이한다. 모든 전이는 서버 트랜잭션에서 거점 행을 잠근 뒤 처리한다.

- **AVAILABLE → ACTIVE**: 같은 탑·층에 소유자가 없으면 서버가 최초 요청을 점령으로 확정하고 15분 종료시각과 보상 스냅샷을 기록한다.
- **ACTIVE → CONTESTED**: 다른 로그인 사용자가 같은 탑·층에서 쟁탈을 요청하면 30초 응답창과 개입전 상태를 만든다.
- **CONTESTED → ACTIVE(기존 소유자)**: 소유자가 방어하고 개입전에서 승리한다.
- **CONTESTED → ACTIVE(도전자)**: 소유자가 포기하거나 도전자가 개입전에서 승리한다. 새 종료시각은 승리 시점의 기존 남은시간에 그 절반을 더한 값이다.
- **ACTIVE → COMPLETED**: 종료시각 이후 소유자만 보상을 1회 정산한다.
- **ACTIVE/CONTESTED → ABANDONED**: 소유자가 포기 귀환한다. 대기 도전자가 있으면 가장 먼저 접수된 요청이 승계하고, 없으면 진행을 삭제한다.

## 동시 요청 우선순위

모든 요청은 클라이언트 UUID를 멱등 키로 사용한다. 동일 거점의 요청은 `requested_at ASC, request_id ASC` 순서로 확정한다. 서버 접수시각이 같아도 UUID가 최종 순서를 고정한다. 이미 처리한 UUID는 기존 결과를 반환한다.

1. 이미 완료·만료된 소유 상태를 정리한다.
2. 빈 거점이면 첫 요청을 점령으로 확정한다.
3. 소유자의 포기는 현재 도전자 또는 가장 빠른 대기 요청보다 먼저 적용된다.
4. 소유 중인 거점에는 가장 빠른 다른 사용자의 요청 하나만 개입전을 연다. 나머지는 대기한다.
5. 남은시간이 1분 이하이면 응답 만료시각은 `요청시각 + 남은시간 × 1.5`; 그 외에는 30초다.

## 개입전과 약탈

개입전은 서버가 보관하는 HP·공격·방어·현재 행동자·행동 번호로 진행한다. `BASIC`과 `GUARD`만 허용하며 행동 번호는 정확히 1씩 증가한다. 승패가 확정되면 한 트랜잭션에서 소유권, 남은시간 승계, 임시 재료 약탈, 장비 1개 약탈 또는 15% 파괴, 양쪽 원정 투영 및 영수증을 함께 기록한다. 영수증의 고유 키로 재시도 중복 지급을 막는다.

공용 상태 변경은 인증된 private Realtime 채널 `resource_stronghold`에 방송한다.
