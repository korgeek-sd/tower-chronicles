# 탑의 기록 v0.1.26 — 고급 전투 트리거 구현 보고

## 1. 버전 / 저장 스키마

- package version: `0.1.26`
- save schema: `v19`
- migration: 기존 `v18` 저장을 `v19`로 한 번 이전하며, 진행 중 원정에는 `reactivePrepared: { player: null, monster: null }`을 추가한다.
- migration backup key: `tower-record-v1-before-combat-triggers-v19`
- 작업 전 파일 백업: `backups/before-v0.1.26`에 v0.1.25 상태를 보존했다. 기존 백업 충돌은 없었다.

## 2. 작업 전 v0.1.25 상태 확인

실제 코드에서 `MonsterBattleRuntime`, 규칙 우선순위 기반 Monster AI, Monster Skill resolver, 쿨다운, Charge Prepared Action, multi-hit, 양측 ActiveEffect, DOT/HOT/STAT_MODIFIER, 저장 중 runtime 보존, 수동 `PLAYER_TURN`, 도망 시 마지막 Monster AI 행동, BOSS 이벤트의 공통 전투 엔진 연결을 확인했다. 따라서 v0.1.25를 재작성하지 않고 해당 경로를 확장했다. 작업 전 전체 테스트는 217개였고 217개가 성공했다.

## 3. Direct Hit Received Trigger

`src/game/engine/directHits.ts`의 `resolveDirectHits`가 공통 hit 단위 경로다. 기본 공격과 공격 스킬의 각 실제 hit가 HP를 감소시킨 뒤 대상이 살아 있을 때만 `DIRECT_HIT_RECEIVED`를 전달한다. 대상이 해당 hit로 사망하면 반응을 실행하지 않는다. DOT, 이벤트 피해, 단순 HP 변경, 회복에는 이 resolver를 사용하지 않아 trigger가 발생하지 않는다. Multi-hit는 hit마다 피해와 trigger 판정을 순서대로 처리한다.

## 4. Reactive Prepared

원정 runtime에 actor별 단일 슬롯 `reactivePrepared.player`와 `reactivePrepared.monster`를 추가했다. Reactive 준비 스킬은 자기 행동을 소비하며 준비 순간에 쿨다운을 시작한다. 같은 actor가 다시 준비하면 기존 슬롯을 새 준비 상태로 교체한다. 직접 피격 시 `consumeDirectHitReaction`이 슬롯을 먼저 비운 뒤, 기존 actor skill resolver를 통해 반응 스킬을 즉시 실행한다. 반응은 별도 턴이나 turn counter 증가를 만들지 않고 쿨다운도 다시 설정하지 않는다. 진행 원정 저장 및 reload에서 pending 상태를 보존하고, 전투 종료·이벤트 전환·새 조우에서는 정리한다. Charge의 별도 `preparedActionId`는 유지된다.

## 5. Reaction과 Multi-hit

하나의 준비된 반격은 첫 유효 hit에서 선소비되므로 multi-hit 전체에서 한 번만 발동한다. 반응 후 양측이 생존하면 원래 공격의 다음 hit를 계속한다. 반응으로 원래 공격자가 사망하면 남은 hit를 즉시 중단한다. 반응 스킬의 direct hit에는 `allowReactive: false`를 전달해 다른 Reactive를 재귀 발동하지 않도록 고정했다.

## 6. Stack Threshold

기존 `STACK`, `stackCount`, `maxStacks`, `applyEffect`를 재사용했다. `EffectDefinition.thresholdReaction`은 `previousStacks < threshold && newStacks >= threshold`일 때만 실행된다. transition은 같은 actor에서 자기 stack effect 제거, 지정 effect 제거, 지정 effect 적용을 지원한다. max stack에서의 재적용은 crossing이 아니므로 반복 발동하지 않는다. effect가 제거된 뒤 0부터 다시 쌓이면 새 crossing이 가능하다. 최종 ActiveEffect 배열이 저장되므로 reload 뒤에도 중첩과 transition 결과가 유지된다.

## 7. Status-based Monster AI

지원 조건은 다음과 같다.

- 기존: `SELF_HP_BELOW`, `TARGET_HP_BELOW`, `SKILL_READY`
- 신규: `SELF_HAS_EFFECT`, `SELF_MISSING_EFFECT`, `TARGET_HAS_EFFECT`, `TARGET_MISSING_EFFECT`, `SELF_EFFECT_STACKS_AT_LEAST`, `TARGET_EFFECT_STACKS_AT_LEAST`

평가는 `src/game/engine/monsterAi.ts`에서 `hasEffect`와 `effectStacks` 공통 helper를 사용한다. 한 규칙의 조건은 AND이며, 기존과 동일하게 높은 priority와 선언 순서를 따라 결정적으로 선택한다. Charge discharge를 가장 먼저 처리하고, pending Reactive는 정상 Monster AI 선택을 막지 않는다. 알 수 없는 effect ID나 잘못된 stack 조건은 false로 안전하게 fallback하며 DEV validation 오류로도 보고한다.

## 8. UI

`BattleScreen`은 엔진 상태만 표시한다. Charge와 Reactive 준비가 동시에 존재하면 두 경고를 함께 보여 준다. 플레이어와 몬스터 ActiveEffect는 `stackCount > 1`일 때 `×N`을 표시한다. 준비·소비·즉시 발동 및 threshold 결과는 기존 전투 기록 패널에 남는다. 320px과 390×844에서 경고, 칩, 행동 버튼, 아이템 패널을 확인했고 가로 스크롤은 없었다.

## 9. Save / Migration

`v19`는 진행 원정의 actor별 Reactive pending 상태를 영속화한다. `validSave`는 runtime의 definition/prepare/reaction ID와 trigger 형식을 검사하고, 전투 외 phase에는 빈 슬롯만 허용한다. `migrateV18`은 기존 HP, 몬스터 HP, Charge, 효과, 포션, 전리품 등 v18 데이터를 보존한 채 새 슬롯만 초기화한다. 이전 원본은 전용 키에 한 번 백업한 뒤 저장하며 백업 쓰기 실패 시 메인 저장을 덮어쓰지 않는다.

## 18. 다음 업데이트 준비 상태

- **A. Charge boss — READY.** 기존 `preparedActionId`, 우선 discharge, reload, discharge 쿨다운이 production 경로에 있다.
- **B. 피격 stack → threshold → armor break boss — READY.** Reactive reaction skill이 기존 effect application을 사용하고, `applyEffect`가 crossing 시 자기 stack/armor 제거와 exposed 적용을 처리한다. 보스 데이터만 추가하면 된다.
- **C. target effect stack 기반 AI boss — READY.** `TARGET_EFFECT_STACKS_AT_LEAST`가 production AI의 결정적 priority 평가에 연결돼 있다.
- **D. Reactive counter boss — READY.** `DIRECT_HIT_RECEIVED` 준비·선소비·즉시 resolver·저장·cleanup이 production 전투에 연결돼 있다.
- **E. HP condition 기반 multi-pattern boss — READY.** 기존 SELF/TARGET HP 조건, skill ready, effect 조건을 AND로 조합하고 priority로 여러 패턴을 선택할 수 있다.
