# 탑의 기록 v0.1.25 — 몬스터 전투 엔진 통합 구현 보고

## 1. 버전 / 저장 스키마

- package version: `0.1.25`
- save schema: `17 → 18`
- 기존 save key `tower-record-v1` 유지
- v17 저장은 검증 후 v18로 한 번만 이전하며, 진행 중 전투에는 현재 몬스터와 기존 `monsterTurn`을 기준으로 런타임을 만든다.
- 이전 전 원본은 `tower-record-v1-before-monster-runtime-v18`에 한 번 보존한다. 백업 실패 시 메인 저장을 덮어쓰지 않는다.
- 작업 전 파일은 `backups/before-v0.1.25`에 보존했다. 기존 폴더 충돌은 없었다.

## 2. 변경 전 핵심 문제

생산 전투의 `resolveMonsterTurn()`은 몬스터 AI·스킬·쿨다운·준비 행동을 사용하지 않고 기본 공격만 실행했다. `MonsterBattleRuntime`은 원정 저장과 연결되지 않았고, 수동 턴제 화면에는 자동 pass와 미연결 포션 경로가 남아 있었다. guard는 표시만 있고 피해 감소가 없었으며 quick/haste는 공격력 증가로 잘못 연결되어 있었다.

## 3. MonsterBattleRuntime

`Expedition.monsterRuntime`에 현재 전투 런타임을 저장한다. 필드는 정의 ID, 몬스터 턴 번호, 스킬별 쿨다운, `preparedActionId`다. 일반 조우와 보스 조우가 시작될 때 생성하고, 이벤트 진입·전투 종료 때 비운다. 저장 검증과 v17 마이그레이션에 포함되어 새로고침 후에도 그대로 복원된다.

## 4. Monster AI 연결

생산 호출 경로는 `resolveMonsterTurn → beginMonsterTurn → chooseMonsterAction → resolveMonsterAction → useMonsterAction`이다. `SELF_HP_BELOW`, `TARGET_HP_BELOW`, `SKILL_READY`를 지원하며, `SKILL_READY.skillId`는 문자열 ID로 타입을 바로잡았다. 준비 행동, 높은 priority, 선언 순서의 결정적 비교, 첫 유효 행동, 기본 공격 fallback 순서로 선택한다. 잘못된 rule이나 정의는 전투를 멈추지 않고 기본 공격으로 처리한다.

## 5. Monster Skill Resolver

공통 피해 공식과 공통 다중 타격 계산을 재사용한다. 스킬의 `multiplier`와 `hits`를 실제 피해에 반영하고, TARGET/SELF 대상의 기존 ActiveEffect를 적용한다. 피해 없는 자기 강화와 prepare도 행동 한 번을 정상 소비한다. 알 수 없는 효과 ID는 실행하지 않고 읽을 수 있는 로그를 남긴다.

## 6. Monster Cooldown

스킬 해결 후 cooldown을 N으로 설정한다. 몬스터의 다음 자기 턴 시작마다 1씩 줄이며, 0이 된 그 턴부터 다시 사용할 수 있다. 플레이어 행동과 실시간 경과는 몬스터 cooldown을 줄이지 않는다. 플레이어 cooldown도 플레이어 자기 턴 기준 의미를 유지한다.

## 7. Charge Prepared Action

prepare는 피해 없이 몬스터 행동 하나를 소비하고 방출할 스킬 ID를 런타임에 저장한다. 다음 행동 가능한 몬스터 턴에는 AI rule보다 방출이 먼저 실행된다. cooldown은 준비 시점이 아닌 방출 완료 후 설정한다. 일반 공격을 받아도 준비 상태가 유지되고, 저장·새로고침 뒤에도 다음 몬스터 턴에 정상 방출된다.

## 8. Multi-hit

하나의 스킬 행동 안에서 `hits` 수만큼 공통 피해 공식을 각각 적용한다. 각 타격을 전투 로그에서 구분하며, 대상이 중간 타격에 사망하면 남은 타격을 중단한다. 여러 타격이 추가 몬스터 턴을 만들지 않는다. 활 기본 공격도 같은 경로로 2타를 실행한다.

## 9. Effect Engine 연동

몬스터 스킬은 플레이어에게 poison/weaken을, 자신에게 attack_up/defense_up/regen을 적용할 수 있다. DOT/HOT는 기존 createdTurn 규칙을 유지해 생성된 같은 턴에는 발동하지 않고 대상 actor의 다음 자기 턴 종료부터 처리한다. STAT_MODIFIER와 duration 만료도 actor 턴 종료 처리에 포함한다.

## 10. Player Turn 정합성 수정

기본 공격이 가능하면 `hasPlayableBattleAction()`이 항상 행동 가능으로 판단하며 자동 pass 타이머를 제거했다. `passPlayerTurn()`도 공통 플레이어 턴 종료 경로를 사용해 periodic, duration, 사망, 전투 종료를 처리한다. 실시간 `tick()`은 전투 상태와 cooldown을 바꾸지 않는다. 포션 실제 사용은 플레이어 행동 한 번을 소비하고 몬스터 턴으로 이어진다.

## 11. Guard / Quick / Haste 처리

기존 guard 수치인 받는 피해 40% 감소를 `receivedDamage` STAT_MODIFIER로 실제 피해 계산에 연결했다. 반격이나 Reactive Prepared는 추가하지 않았다. quick 스킬과 haste 포션이 잘못 주던 `attack_up`을 제거하고, 현재 수동 턴제에서는 추가 효과가 없음을 UI와 로그에 명시했다. 속도·추가 행동 메커니즘은 아직 구현하지 않았다.

## 12. Flee

도망가기는 플레이어 행동을 소비하고 `pendingFlee`를 설정한다. 이후 몬스터가 공통 AI 경로로 정확히 한 번 정상 행동한다. 준비 중인 스킬은 이 마지막 턴에 방출될 수 있다. 생존하면 기존 안전 귀환 정산, 사망하면 기존 사망 손실을 적용한다. 마지막 턴의 몬스터 DOT 사망도 추가 랜덤 이벤트 없이 기존 정산으로 끝난다.

## 13. Boss Event 통합

BOSS 이벤트의 도전 결과는 `beginEncounter()`를 통해 일반 전투와 같은 `MonsterBattleRuntime`을 만들고 공통 `resolveMonsterTurn()`을 사용한다. 보스 처치 후 `bossKillCountThisExpedition`, `bossDefeated`, 귀환 시 티어 확정, 반복 조우 등 v0.1.24 진행 규칙을 유지했다. 정식 신규 보스 스킬과 보상 배율은 추가하지 않았다.

## 14. Save v17 → v18

v17의 재산, 인벤토리, 장비, 직업, 제작, 조합, HP, 임시 전리품, Silver, 포션, 이벤트, bossTracking, 층과 몬스터를 그대로 복제한다. BATTLE 상태만 현재 몬스터와 `monsterTurn`으로 런타임을 만들며 EVENT/RESULT 상태에는 런타임을 억지로 만들지 않는다. 이전 결과를 v18 validator로 다시 검증한 후 저장한다. 백업 실패와 손상된 런타임은 원본을 유지한 채 오류로 처리한다.

## 15. UI 변경

전투 화면에 `준비 중: [스킬 이름]` 경고를 추가했다. 준비 시작, 방출, 스킬, 효과, DOT/HOT, 다중 타격을 기존 전투 로그에 표시한다. 아이템 버튼은 실제 포션 패널을 열며, 패널 여닫기는 행동을 소비하지 않고 포션 선택만 엔진의 `useBattlePotion()`을 호출한다. 활 기본 공격 카드에는 2타를 표시하고 도망 안내는 적의 정상 행동 후 귀환으로 수정했다.
